# Инцидент 19.09: архивирование записи, которой нет в сторе

## Что случилось

При очистке памяти (98%) агент заархивировал в «Архив памяти.md» ДВЕ записи перед удалением — но одна из них («Memory rule: when a decision changes… use supersede…») оказалась не записью стора, а системной вставкой из промпта (блок Memory rule, который движок добавляет в каждый ход). `memory(remove, old_text=…)` честно отказал: «No entry matched». Пришлось патчить архив, чтобы убрать фиктивную запись. Потеря: ~4 лишних хода.

## Правило

**System-prompt insertions are NOT store entries.** Текст, видимый в промпте или retrieval-паке, может вообще не иметь строки в сторе. Перед связкой «заархивировать → удалить/заменить»:

1. Подтвердить существование записи: живой `memory(read)` вернул её, ИЛИ она есть в `current_entries` дампа ошибки, ИЛИ id получен из ответа самого стора в этой сессии.
2. Только после подтверждения — писать в архив.
3. Если архив уже запачкан фиктивной записью — убрать её из архива (архив обязан оставаться правдивым, см. «archive truthfulness» в SKILL.md).

## Симптом

`remove`/`replace` по тексту, который «вот же виден в промпте», падает с «No entry matched» — и это не баг стора, а признак того, что текст не из стора. Не ретраить с парафразами: сначала проверить существование.
