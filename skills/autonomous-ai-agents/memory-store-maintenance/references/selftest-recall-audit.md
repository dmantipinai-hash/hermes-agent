# Self-test / recall audit памяти Локи (рецепт, проверен живьём 31.08)

Дима периодически просит «проверь, как работает память» — факты, граф, скорость, экономика. Рецепт из живого прогона 31.08.2026.

## Процедура

1. **Батч 4–7 параллельных `memory read`**: каждый факт, названный пользователем + 1 опечатка-проба (ожидаемо 0 результатов — FTS буквальный, fuzzy-поиска нет) + 1 проба ё-фолдинга (запрос без «ё» обязан найти запись с «ё» — P7) + 1 контрольный факт с другой темы.
2. **`possible_tensions` в выдаче — подсказки, не вердикты.** Каждого кандидата разбирать руками: 31.08 оба «конфликта» оказались ложными на генерических общих термах («димы, локи», score 0.03–0.05).
3. **Скорость** — прямой SQL по `~/.hermes/memories/memory.db`:
   - Реальные таблицы: `memories`, `memories_fts` (+ `_data/_idx/_docsize/_config`), `memory_links` (граф supersede), `memory_aliases`, `memory_recall_log`, `meta`. НЕ `memory_fts` — такого имени нет.
   - Статистика графа: `SELECT 'links', count(*) FROM memory_links UNION ALL ...` — 31.08: 124 записи / 119 active / 5 deprecated / 19 links / 52 aliases / 527 recall-строк.
   - Замеры: все FTS/LIKE — < 10 мс (real 0.00).
4. **Отчёт пользователю**: найдено/не найдено по каждому факту, граф (links/aliases/deprecated, конфликты да/нет), латентность, токен-стоимость (числа — в agent-token-economy, замер 31.08: батч 7 поисков ≈ 5–8k токенов ≈ $0.01; полный аудит ≈ $0.03 по прайсу).

## Главный pitfall: recall зависит от формулировки запроса

Один `read` с неудачными ключами может НЕ вытащить хранимый факт. Живой кейс 31.08: запрос «продление подписка оплата» не нашёл запись «кодинг-план Z.AI куплен 9.02.2026 на год за $360» (в user-сторе), хотя она существовала; на следующий день она сама всплыла авто-реинъекцией при совпадении слов в сообщении пользователя.

Правило: прежде чем заявлять «факта нет в памяти»:
1. 2–3 варианта ключей (название продукта + глаголы «купил/продлил/оплатил», обе витрины `memory` и `user`);
2. проверить references/ скиллов по теме — факт может жить в скилле, а не в памяти (кейс: детали кодинг-плана были в agent-token-economy/references/zai-coding-plan-credits.md).

«Не нашёл с одного запроса» ≠ «нет в памяти».

## Известные ограничения поиска (говорить честно в отчёте)

- Опечатки не прощает («куление» → 0). Русской морфологии нет — искать корнями слов.
- Семантического поиска нет — решения P4 (embeddings не поднимаем, окупаемость 13% < 20%).
